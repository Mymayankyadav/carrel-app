# L6 Distraction — incremental implementation (2026-10-28)

Owner: ORC acting as L6. Branch `v2/l6`. Target: Phase 2 of `docs/PLAN-v2.md` D8.

## Delivered in this draft
- Quiet 60-second urge-surf sheet with non-announcing SVG countdown, Back to work and Log drift.
- Existing Today L1 hook uses one durable `noticeNow()` record; Log drift returns to original 1/5/15-minute chips. The reporting window now remains valid throughout the full 60-second exercise (regression covered).
- Labs `urgesurf` default on; opt out retains previous inline behavior.
- Weekly drift summary card with seven-day sparkline on Sundays or rising-drift weeks.
- Android `UsageReader.kt` with explicit special `PACKAGE_USAGE_STATS` OS grant, foreground time-window clipping, app-open counts and a default allowlist of ten social/video apps. No URLs, notifications, messages or screen content are read.
- `CarrelLivePlugin` methods `hasUsageAccess`, `openUsageAccess`, `sessionUsage`; native `detectDrift` remains **off by default** and requires both user opt-in and OS Usage Access. Editable monitored-app list stored on device.
- Settings › Notifications toggles / app chips, access re-check on resume, detection at completed study session (≥10 min) and subject switches.
- Only sessions with ≥2 minutes of allowlisted foreground activity write aggregated metadata to the existing offline queue in `usage/<date>`; toast offers a **separate Log action** that can attribute detected minutes to drift. No automatic modification of study entries.
- Node tests for single-notice, weekly card, app allowlist, queued write shape, stale session edits, consent/app-list revocation during an in-flight query, old APK gating and Undo isolation. Kotlin JVM clipping tests, mock Playwright 390/1280 light/dark acceptance.
- Compatibility: the native plugin explicitly advertises `usageDetectionSupported`; older APKs cannot offer a dead-end Usage Access control even if the Capacitor JS proxy exposes the method name.
- Consent: the JS bridge rejects stale data after opt-out, allowlist edits or a sign-out/login (including to the same account); the native worker rechecks OS permission, native opt-in and the allowed package list both before and after reading events. Sign-out clears in-memory usage preferences, while permission-screen failures retain the already saved native opt-in and explain the still-missing grant.
- A detected-usage toast now expires after 2 minutes or immediately upon opt-out, revocation, app-list change or sign-out; no permanent dead action.
- Android settings disclose broad OS usage-access scope, and that only selected app names, foreground minutes and open counts are synced.
- Data contract confirmed: existing `watchColl('usage')` / `W().update('usage/<date>')` sync and D8 shape, no schema migration. Automatic detection writes do not occupy the user's Undo history.
