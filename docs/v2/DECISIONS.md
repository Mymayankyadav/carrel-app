2026-10-29 · QA/ORC · Merge overlapping free windows before auto-planning; reject non-finite and invalid exam-plan inputs and cap day capacity to 24h · Prevent double-booking, inflated availability, and unbounded loops without touching user data.
2026-10-29 · QA/ORC · Scope offline pending writes to the authenticated UID and clear cached state on account switch; quarantine legacy unowned queue rather than replay it · Prevent cross-account writes and display leakage without silently deleting old unsent edits.
2026-10-29 · QA/ORC · Serialize per-account IndexedDB operations across adapters and preserve per-path mutation revisions until network reads settle · Prevent sign-out cache resurrection and stale fetches overwriting realtime changes without changing server data or app UX.
2026-10-29 · QA/ORC · Treat IDB transaction completion as the only durable write success, retry failed writes/deletes at most three times, and return explicit cache-clear success · Avoid ghost caches after transient aborts and prevent queue overlap while retaining bounded failure behaviour.
2026-10-29 · QA/ORC · Persist failed sign-out cache deletion as a device-local cleanup obligation, show an actionable signed-out warning, and skip stale hydration until durable deletion · Avoid silent retention of offline documents without blocking account access or weakening account isolation.
2026-10-29 · QA/ORC · Only INITIAL_SESSION and SIGNED_IN may establish or switch account identity; TOKEN_REFRESHED and USER_UPDATED are applied only to the active UID, and only a matching token refresh may lift read-only mode · Prevent delayed cross-account auth notifications from replacing native credentials or replaying an offline write queue.
2026-10-29 · QA/ORC · Treat INITIAL_SESSION only as an initial bootstrap, never an account switch after explicit sign-in or sign-out · Prevent delayed auth snapshots from restoring another account's cache or hiding an active session.
2026-10-29 · QA/ORC · Drain Supabase auth events in a single deferred receipt-ordered batch; skip superseded sign-ins/metadata and clear a coalesced signed-out UID via a disk-only adapter without deleting the previously active account's cache · Prevent transient wrong-account queue replay and preserve offline cache deletion during rapid account transitions.
2026-10-29 · QA/ORC · Fence every subscription callback and historical range-fetch resolution to its originating database adapter and fetched-set generation · Prevent cross-account data display, stale auth errors, and fetch-marker corruption after rapid account changes.
2026-10-29 · QA/ORC · Assign each realtime subscription pass a generation token and bind retry timers to its adapter and generation; ignore unsubscribed callbacks even on the same account · Prevent stale reconnect snapshots, errors and already-queued retries from replacing newer state.
2026-10-29 · QA/ORC · Fence historical query merges by per-account document revisions, live-window ownership and newer completed overlapping range coverage; remove absent historical rows only when the query remains authoritative · Prevent reconnect and out-of-order fetches from restoring deleted or stale study data.
2026-10-29 · QA/ORC · Never discard an account-scoped offline write merely because retries were exhausted or a quota/validation error occurred; cap retry delay, retain the persisted operation and warn once · Avoid irreversible local data loss without remote acknowledgement while keeping existing auth and per-path ordering safeguards.
2026-10-29 · QA/ORC · Treat localStorage write/read-back failure as an explicit failed user action, atomically persist all writes before network dispatch, and keep the previous durable queue unchanged · Never report an offline-safe save when the device cannot retain the edit through reload.
2026-10-29 · QA/ORC · Keep remotely acknowledged writes in memory until their outbox deletion is durable; retry account-fenced cleanup and warn on failure · Avoid silent stale outbox replay during a live session when local storage fails after remote success.
2026-10-29 · QA/ORC · Bind new offline outboxes to the Supabase JWT session ID and quarantine pre-upgrade queues for explicit recovery; retry failed sign-out deletion without claiming disk erasure · A new login must never automatically replay writes from a session whose user chose to discard them, even when localStorage deletion fails.
2026-10-29 · QA/ORC · Reject local outbox updates when another tab has changed the last loaded snapshot, including remote-ack deletion, and warn with a reload path · Preserve the other tab's offline edits rather than silently overwriting them; simultaneous-write atomicity still requires a separate cross-tab locking design.
2026-10-29 · QA/ORC · Before sign-out, check the durable same-session outbox even when the current tab has no in-memory edits; abort if identity changes while discard confirmation is open · Avoid silently discarding another tab's queued work while preserving explicit sign-out semantics.
2026-10-29 · QA/ORC · Treat unreadable/corrupt device outbox storage as unknown rather than empty during sign-out, and invalidate discard consent when another tab changes the durable queue before sign-out · Avoid silent offline-edit loss while preserving explicit user sign-out; cross-tab atomicity remains issue #90.
2026-10-29 · QA/ORC · Use checked localStorage reads for offline outbox restore, enqueue and acknowledgement cleanup; reject corrupt, wrong-shaped or inaccessible queues and require a fresh restore after startup read failure · A failed read is not an empty queue, and must never authorize overwriting unsent user edits.
2026-10-29 · QA/ORC · Prototype immutable per-operation, account/session-scoped localStorage journal keys before replacing the shared offline queue · Independent tab writes avoid array lost updates, while delivery ownership, sign-out, migration and real two-context acceptance remain explicit gates; client delivery is still at least once.
2026-10-29 · QA/ORC · Store each multi-document user action as one immutable journal batch record, retaining legacy single-op reads · An interrupted or quota-failed save must not publish only part of an action across tabs; runtime migration remains separately gated.
2026-10-29 · QA/ORC · Prototype account/session-scoped Web Locks ownership for journal delivery, with fail-closed no-lock fallback and identity checks before sends/acknowledgements · Prevent simultaneous tab replay and unsafe localStorage leases; keep production queue unchanged until append ordering, migration and sign-out coordination are proven.
2026-10-29 · QA/ORC · Assign journal action sequence under the same account/session Web Lock used by delivery, reject mixed/unsequenced pending data and duplicate order rather than relying on localStorage enumeration · Preserve same-path FIFO and crash-safe append ordering without migrating or touching the production shared queue.
2026-10-29 · QA/ORC · Gate legacy session-queue migration behind a read-only, exact-session preflight with byte-for-byte source revalidation and an empty journal; do not copy, clear or switch production authority yet · A snapshot cannot make simultaneous legacy producers atomic, and automatic import could replay intentionally discarded edits.
2026-10-30 · QA/ORC · Stage only a bounded (≤256 operations) exact-session legacy queue under the journal Web Lock using a durable source-byte marker and reserved immutable journal record; preserve the legacy source and fail closed on races, ambiguous records, unavailable locks, or quota errors · Make crash recovery testable without claiming that legacy writers participate in the lock or that production authority has switched.
2026-10-30 · QA/ORC L9 · Validate real calendar days and optional deadline times before Quick Capture creates a write set, and reject unexpected capture types · A syntactically valid but impossible date could otherwise create hidden plans or unusable due dates; keep all valid v1 and v2 capture writes unchanged.
2026-10-30 · QA/ORC · Stage legacy session outboxes in deterministic, resumable 256-operation journal chunks under the existing Web Lock, but never promote or deliver those copies · Large queues need bounded crash recovery; legacy writers are not lock-aware, so source-byte verification is not an atomic authority handoff.
2026-10-30 · QA/ORC · Never deliver or generically acknowledge reserved legacy staging records, even when normal records precede them in localStorage enumeration · A copy is not an authoritative outbox; accidental use of the prototype delivery coordinator must not send duplicate user edits or erase staged data before a separately reviewed handoff.
2026-10-30 · QA/ORC #90 · Refuse remote delivery of two or more unsequenced journal actions while retaining single-action compatibility · localStorage key order is not FIFO, and reversing same-path edits could silently corrupt the eventual remote state; ordered Web Lock appends are the safe path. No production cutover.
2026-10-30 · QA/ORC #90 · Accept legacy `delete` operations without a serialized `data` field in the isolated migration preflight and journal, but retain strict `set`/`update` payload validation · JSON serialization legitimately omits `data: undefined` for deletes; rejecting it would strand valid offline queues. This is not a production authority switch.
2026-10-30 · QA/ORC #90 · Prototype a session-scoped legacy producer append under the journal Web Lock, fail closed on staging markers and uncertain storage, but do not activate it in sync.js · Existing v1 tabs still write without that lock, so enabling a partial migration could strand or lose offline edits.
2026-10-30 · QA/ORC #90 · Require an exact durable queue snapshot and exact acknowledged FIFO prefix under the same session Web Lock for experimental legacy ack cleanup; fail closed on stale tabs and uncertain writes · An unlocked or stale acknowledgement could erase another tab's pending edits. Old v1 tabs remain unfenced; no production cutover.
2026-10-30 · QA/ORC #90 · Preserve immutable, session-scoped recovery receipts before experimental legacy array writes and audit tagged actions without auto-replay or retirement · A stale localStorage view can lose an edit even when Web Locks serialize writers; the receipt preserves evidence and payload while production cutover remains prohibited.
2026-10-31 · QA/ORC L9 · Keep Quick Capture open until its write set is durably enqueued; on storage or cross-tab failure preserve typed content and editable overrides with a retryable error · Closing before commit returned could irreversibly lose an unsaved task, deadline, block or Claude question.
2026-10-31 · QA/ORC L10 · Close Claude coach Accept/Dismiss only after `commit()` durably queues the whole write set · Storage quota and cross-tab conflict errors must leave the original suggestion and retry action visible; preserve existing offline and v1 compatibility semantics.
